01 Prerequisites

  • Python 3.12+ and uv (fast installs, lockfile, runner).
  • For local mode: Ollama running (ollama serve) with a model pulled (e.g. ollama pull llama3.1:70b), and a Speaches server with a Kokoro TTS model.
  • For cloud mode: an OpenAI API key with access to the configured chat + TTS models.
  • The member dataset — already preserved in this repo under seimas/ and seimas_members_data.js; copy/convert into data/members/ in Phase 2.
  • Docker (optional) for the containerised / compose stack.

04 Implementation roadmap

Build inside-out: models and the vote first (pure, fully tested), then I/O around them. You can demo after every phase.

Phase 0 — Scaffold & health

Create the package, the app factory, and a health endpoint. Dependencies are wired through a single AppServices container resolved by a FastAPI dependency.

src/posedis/main.py 
from contextlib import asynccontextmanager
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles
from .config import Settings
from .services.container import AppServices

def create_app(settings: Settings | None = None) -> FastAPI:
    settings = settings or Settings()

    @asynccontextmanager
    async def lifespan(app: FastAPI):
        app.state.services = await AppServices.create(settings)
        yield
        await app.state.services.aclose()

    app = FastAPI(title="Posėdis", lifespan=lifespan)
    from .api import members, sessions, stream, tts
    for r in (members.router, sessions.router, stream.router, tts.router):
        app.include_router(r)

    @app.get("/healthz")
    def health():
        return {"ok": True, "providers": app.state.services.configured_providers()}

    app.mount("/", StaticFiles(directory="src/posedis/web/static", html=True), name="web")
    return app

app = create_app()
✅
Done when: uv run uvicorn posedis.main:app serves /healthz → {"ok": true, ...}.

Phase 1 — Domain model & the vote (test-first)

Create models/events.py, models/vote.py, models/session.py exactly as in Architecture §4. This is the heart of the product; write the tests first.

tests/test_vote.py 
import pytest
from pydantic import ValidationError
from posedis.models.vote import Vote

def test_result_is_derived_by_majority():
    v = Vote(question="x", registered=138, **{"for": 89}, against=31, abstain=18)
    assert v.cast == 138 and v.quorum_met and v.result.value == "passed"

def test_rejected_and_no_quorum():
    v = Vote(question="x", registered=70, **{"for": 30}, against=38, abstain=2)
    assert v.result.value == "rejected" and not v.quorum_met

def test_cast_cannot_exceed_141():
    with pytest.raises(ValidationError):
        Vote(question="x", registered=141, **{"for": 100}, against=50, abstain=10)

def test_faction_breakdown_must_reconcile():
    with pytest.raises(ValidationError):
        Vote(question="x", registered=10, **{"for": 5}, against=5, abstain=0,
             byFaction=[{"party": "LSDP", "for": 4, "against": 5, "abstain": 0}])
✅
Done when: these tests pass and a Session without a vote raises (FR-16). The vote is now correct independent of any model or network.

Phase 2 — Member repository

Load the preserved 141-member dataset once at startup. The richest source is seimas_members_data.js (name, party, personality, goals, abilities, constraints/limitations); the Markdown profiles under seimas/ add long-form biography. Convert to JSON in data/members/members.json and load with Pydantic.

src/posedis/services/members.py 
import json
from pathlib import Path
from posedis.models.member import Member

class MemberRepository:
    def __init__(self, members: list[Member]):
        self._by_id = {m.id: m for m in members}

    @classmethod
    def from_file(cls, path: Path) -> "MemberRepository":
        rows = json.loads(path.read_text(encoding="utf-8"))
        return cls([Member.model_validate(r) for r in rows])

    def all(self) -> list[Member]: return list(self._by_id.values())
    def get(self, mid: str) -> Member | None: return self._by_id.get(mid)
    def by_party(self, party: str) -> list[Member]:
        return [m for m in self.all() if m.party == party]

A one-off conversion script (scripts/convert_members.py) reads the legacy SEIMAS_MEMBERS_DATA array and writes members.json, assigning each member a stable voice.

Phase 3 — Prompts & normalization

Port the bilingual prompt scaffolding (structural arc + ideological guardrails + JSON schema + the mandatory-vote instruction) into services/prompts.py, and implement services/normalize.py per Architecture §5. Normalization is pure and fully unit-testable with hand-written messy dicts.

🗳️
Prompt must demand the vote. Both the system and user prompts instruct the model to emit at least one vote event with procedure, registered count (quorum ≥71/141), exact Už/Prieš/Susilaikė, a per-faction breakdown that sums to the totals, the result, and any dissenters — in the session language.

Phase 5 — Sessions API & store

Wire POST /api/sessions (generate → normalize → validate → save), plus list/fetch, and implement SessionStore (JSON on disk). The handler shape is in Architecture §6.

tests/test_api.py 
import pytest
from httpx import ASGITransport, AsyncClient
from posedis.main import create_app

@pytest.mark.asyncio
async def test_generate_session_contains_a_valid_vote(app_with_fake):
    transport = ASGITransport(app=app_with_fake)
    async with AsyncClient(transport=transport, base_url="http://t") as c:
        r = await c.post("/api/sessions", json={"topic": "4-day week", "mode": "local"})
    assert r.status_code == 200
    body = r.json()
    votes = [e for e in body["events"] if e["type"] == "vote"]
    assert votes and votes[0]["vote"]["result"] == "passed"

Phase 7 — TTS & voice mapping

Implement SpeachesTTS and OpenAITTS against SpeechSynthesizer; map each member to a stable voice (Architecture §10). Cache audio under sessions/{id}/audio/{i}.{fmt}. Wire POST /api/tts and the per-event audio endpoint.

Phase 8 — Frontend

Build web/templates/index.html + web/static/js/app.js using the shared design system (these very docs' site.css). Implement: setup panel → POST /api/sessions; broadcast stage consuming the SSE stream; the vote-report renderer; members modal; audio + optional WebGL face.

web/static/js/app.js — vote frame (essence) 
const es = new EventSource(`/api/sessions/${id}/events?speed=${speed}&tts=${tts}`);
es.addEventListener("frame", (e) => {
  const ev = JSON.parse(e.data);
  if (ev.type === "vote") renderVoteReport(ev.vote);   // balsavimo protokolas
  else renderSpeech(ev);
  if (ev.audioUrl) playAudio(ev.audioUrl);
});
es.addEventListener("end", () => es.close());

05 Provider integration guides

Ollama — chat with JSON output

POST {OLLAMA_BASE_URL}/api/chat
{ "model": "llama3.1:70b", "format": "json", "stream": false,
  "messages": [ {"role":"system","content":"..."}, {"role":"user","content":"..."} ] }
# → { "message": { "content": "<JSON string>" }, ... }  →  json.loads(content)

OpenAI — Responses API with a schema

POST https://api.openai.com/v1/responses          # Authorization: Bearer $KEY
{ "model": "gpt-5-mini", "input": [ ...system+user... ],
  "text": { "format": { "type": "json_schema", "name": "session", "schema": { ... } } } }
# Build the schema from Session.model_json_schema(); parse the JSON output.

Speaches / OpenAI — text to speech

POST {SPEACHES_BASE_URL}/audio/speech              # OpenAI-compatible
{ "model": "speaches-ai/Kokoro-82M-v1.0-ONNX", "voice": "af_heart",
  "input": "<speech text>", "response_format": "mp3" }
# → audio bytes. Cloud: same shape at api.openai.com with model gpt-4o-mini-tts.
⚠️
CORS & timeouts. Generation can take minutes — use a generous httpx timeout (≈600 s). When Speaches is hit from a browser dev server, set its ALLOW_ORIGINS explicitly; in this app TTS is proxied server-side, avoiding browser CORS entirely.

06 Testing strategy

  • Domain (most coverage): vote invariants, quorum edges, result derivation, faction reconciliation, “session must contain a vote”.
  • Normalization: messy/flat/LT-keyed/EN-keyed dicts all normalize into valid votes; breakdown-vs-total conflicts resolve to the breakdown.
  • API: generate/list/fetch with the FakeGenerator (no network); SSE emits frames in order and ends.
  • Providers: mock httpx responses; assert request shape and that bad payloads trigger the single repair retry then a clean error.
  • Frontend smoke: a generated session renders a vote report whose displayed totals equal the model's.

07 Coding standards

  • Full type hints; mypy --strict clean. Pydantic v2 models for every boundary (request, response, provider payloads).
  • ruff for lint + format (line length 100). Small, focused functions; comment only non-obvious logic.
  • Async I/O throughout (httpx, FastAPI); never block the event loop.
  • Providers behind Protocols; no provider name leaks into API or domain code.
  • Secrets only via Settings/request; never logged, never written to session files.
  • Bilingual: every user-facing string has LT + EN; preserve Lithuanian diacritics (UTF-8 everywhere).
