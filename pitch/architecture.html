Document 02 · Architecture

One Python service. No lock-in.

A single FastAPI application serves the presentation-styled frontend and a typed JSON API. Pydantic v2 models are the contract: they validate every LLM response and make the recorded vote self-consistent by construction. Providers (Ollama, OpenAI, Speaches) sit behind protocols, so local and cloud are interchangeable.

01 System overview

The browser loads a static, presentation-styled single-page UI from the same FastAPI process that exposes the API. Generation and synthesis are server-side and provider-agnostic. The recorded vote is normalized then strictly validated before anything is stored or streamed.

04 Domain model

Events are a discriminated union on type. A SpeechEvent covers opening / speech / closing; a VoteEvent carries a validated Vote. A Session must contain at least one vote (FR-16).

src/posedis/models/events.py 
from __future__ import annotations
from enum import Enum
from typing import Annotated, Literal, Union
from pydantic import BaseModel, Field

class EventType(str, Enum):
    OPENING = "opening"
    SPEECH  = "speech"
    VOTE    = "vote"
    CLOSING = "closing"

class BaseEvent(BaseModel):
    time: float = Field(ge=0)        # minutes from session start
    timestamp: str                   # wall clock "HH:MM"
    update: str | None = None        # ticker line

class SpeechEvent(BaseEvent):
    type: Literal[EventType.OPENING, EventType.SPEECH, EventType.CLOSING] = EventType.SPEECH
    speaker: str
    party: str | None = None
    title: str | None = None
    text: str

class VoteEvent(BaseEvent):
    type: Literal[EventType.VOTE] = EventType.VOTE
    speaker: str | None = None       # chair announcing the result
    party: str | None = None
    title: str | None = None
    text: str | None = None          # spoken announcement (TTS source)
    vote: Vote                       # validated, reconciled — see §4.x

Event = Annotated[Union[SpeechEvent, VoteEvent], Field(discriminator="type")]

4.x The vote model — transparent by construction

🗳️
Invariants (PRD FR-16…21). Total seats = 141; quorum ≥ 71. Votes cast = Už+Prieš+Susilaikė ≤ 141 and ≤ registered. Result = majority of those voting (abstentions excluded). The per-faction breakdown must reconcile with the totals. These hold by validation, not by trust.
src/posedis/models/vote.py 
from enum import Enum
from pydantic import BaseModel, Field, computed_field, model_validator

TOTAL_SEATS = 141
QUORUM = 71                           # at least half of all members

class VoteResult(str, Enum):
    PASSED = "passed"
    REJECTED = "rejected"

class FactionTally(BaseModel):
    model_config = {"populate_by_name": True}
    party: str
    for_: int = Field(0, ge=0, alias="for")   # "for" is reserved → alias
    against: int = Field(0, ge=0)
    abstain: int = Field(0, ge=0)

class Vote(BaseModel):
    model_config = {"populate_by_name": True}
    question: str
    procedure: str = "Atviras vardinis balsavimas elektronine sistema"
    threshold: str = "Paprasta balsavusiųjų dauguma"
    registered: int = Field(ge=0, le=TOTAL_SEATS)
    for_: int = Field(ge=0, alias="for")
    against: int = Field(ge=0)
    abstain: int = Field(ge=0)
    result: VoteResult | None = None
    by_faction: list[FactionTally] = Field(default_factory=list, alias="byFaction")
    notable: list[str] = Field(default_factory=list)

    @computed_field
    @property
    def cast(self) -> int:
        return self.for_ + self.against + self.abstain

    @computed_field
    @property
    def quorum_met(self) -> bool:
        return self.registered >= QUORUM

    @model_validator(mode="after")
    def _enforce_invariants(self) -> "Vote":
        if self.cast > TOTAL_SEATS:
            raise ValueError(f"votes cast ({self.cast}) exceed {TOTAL_SEATS} seats")
        if self.registered < self.cast:
            raise ValueError("registered members cannot be fewer than votes cast")
        derived = VoteResult.PASSED if self.for_ > self.against else VoteResult.REJECTED
        if self.result is None:
            self.result = derived
        if self.by_faction:
            cols = (
                sum(f.for_ for f in self.by_faction),
                sum(f.against for f in self.by_faction),
                sum(f.abstain for f in self.by_faction),
            )
            if cols != (self.for_, self.against, self.abstain):
                raise ValueError(f"faction breakdown {cols} != totals")
        return self

The model is strict: it raises on anything that cannot be true in the chamber. Real LLM output is often almost right, so a lenient normalization step runs first and repairs it into a shape this model accepts — that is the FR-21 guarantee.

src/posedis/models/session.py 
from datetime import datetime
from pydantic import BaseModel, Field, computed_field, model_validator
from .events import Event, VoteEvent
from .member import Language  # "lt" | "en"

class Session(BaseModel):
    id: str
    title: str
    topic: str
    language: Language = Language.LT
    created_at: datetime
    duration_minutes: int = Field(ge=1)
    events: list[Event]
    audio: "AudioMeta | None" = None

    @computed_field
    @property
    def total_events(self) -> int:
        return len(self.events)

    @model_validator(mode="after")
    def _must_contain_vote(self) -> "Session":   # FR-16
        if not any(isinstance(e, VoteEvent) for e in self.events):
            raise ValueError("a session must contain at least one recorded vote")
        return self

05 Normalization — making “almost right” add up

Before strict validation, SessionNormalizer repairs the raw provider dict: it accepts nested or flat vote fields, LT or EN keys, coerces counts, defaults procedure/threshold by language, derives the result, lifts registered to at least the votes cast, and — when a faction breakdown disagrees with the totals — rescales the totals to the breakdown (the per-member detail is treated as ground truth). The output is then handed to Vote(**data), which must accept it.

src/posedis/services/normalize.py 
def normalize_vote(raw: dict, *, language: str) -> dict:
    v = raw.get("vote") if isinstance(raw.get("vote"), dict) else raw

    def pick(*keys, default=0):
        for k in keys:
            if v.get(k) is not None:
                return v[k]
        return default

    fa = max(int(pick("for", "forVotes", "uz", "už")), 0)
    ag = max(int(pick("against", "againstVotes", "pries", "prieš")), 0)
    ab = max(int(pick("abstain", "abstainVotes", "susilaike", "susilaikė")), 0)

    factions = [
        {"party": f.get("party") or f.get("faction") or "—",
         "for": int(f.get("for", 0)), "against": int(f.get("against", 0)),
         "abstain": int(f.get("abstain", 0))}
        for f in v.get("byFaction", []) if isinstance(f, dict)
    ]
    # If a breakdown exists, trust it: rescale headline totals to its sums.
    if factions:
        fa = sum(f["for"] for f in factions)
        ag = sum(f["against"] for f in factions)
        ab = sum(f["abstain"] for f in factions)

    cast = fa + ag + ab
    registered = min(max(int(pick("registered", "present", default=cast)), cast), 141)
    lt = language != "en"
    return {
        "question": v.get("question") or raw.get("title") or ("Dėl rezoliucijos" if lt else "On the resolution"),
        "procedure": v.get("procedure") or ("Atviras vardinis balsavimas elektronine sistema" if lt
                       else "Open roll-call vote via the electronic system"),
        "registered": registered, "for": fa, "against": ag, "abstain": ab,
        "byFaction": factions,
        "notable": [str(x) for x in v.get("notable", []) if x],
    }  # result is derived by the Vote validator
🔁
Two layers, one guarantee. Normalization is forgiving; the model is strict. If the normalizer cannot produce a valid vote, the session generation retries once with a corrective prompt, then fails loudly — invalid data is never shown (NFR-3).

@router.post("/api/sessions", response_model=Session)
async def generate(req: GenerateRequest, app: AppServices = Depends(get_services)) -> Session:
    members = app.members.all()
    raw     = await app.generators[req.mode].generate(req, members)
    data    = app.normalizer.normalize(raw, language=req.language)   # §5
    session = Session.model_validate(data)                            # §4 strict
    app.store.save(session)
    if req.tts.enabled:
        app.tts_scheduler.schedule(session, req)                     # background
    return session

07 Generation pipeline

request ─▶ MemberRepository.all()
        ─▶ PromptBuilder.build(topic, language, members)      # system + user, schema-aware
        ─▶ generators[mode].generate(...)  ──▶ raw dict (JSON from the model)
        ─▶ SessionNormalizer.normalize(raw, language)         # repair, reconcile vote
        ─▶ Session.model_validate(data)                       # STRICT; must contain a vote
            │  on ValidationError ─▶ retry once w/ corrective prompt ─▶ else 422
        ─▶ SessionStore.save(session)                         # sessions/{id}.json
        ─▶ [tts] schedule per-event synthesis (background / streamed)
        ─▶ return Session

The PromptBuilder embeds the JSON schema, the structural arc (opening → briefing → speeches → recess → debate → resolution → recorded vote), bilingual ideological guardrails, and the mandatory-vote instruction. It mirrors the proven prompt scaffolding of the prototype, restated for the strict schema.

08 Live streaming (SSE)

For live playback the client opens an SSE stream. The server paces events by their time deltas scaled by speed; when TTS is on, it synthesises lazily and emits an audio URL with each event so playback can begin immediately (FR-10).

src/posedis/api/stream.py 
@router.get("/api/sessions/{sid}/events")
async def events(sid: str, speed: float = 1.0, tts: bool = False,
                 app: AppServices = Depends(get_services)):
    session = app.store.load(sid)

    async def gen():
        prev = 0.0
        for i, ev in enumerate(session.events):
            await asyncio.sleep(max(0.0, (ev.time - prev) * 60 / max(speed, 0.01)))
            prev = ev.time
            payload = ev.model_dump(by_alias=True, mode="json")
            if tts and getattr(ev, "text", None):
                payload["audioUrl"] = f"/api/sessions/{sid}/audio/{i}"
            yield {"event": "frame", "data": json.dumps(payload)}
        yield {"event": "end", "data": "{}"}

    return EventSourceResponse(gen())

09 Providers behind protocols

Generators and synthesizers implement small Protocols, registered by mode. Adding a provider is a new class — no caller changes.

src/posedis/services/generation/ollama.py (essence) 
class OllamaGenerator:
    def __init__(self, client: httpx.AsyncClient, base_url: str, model: str): ...

    async def generate(self, req, members) -> dict:
        prompt = PromptBuilder(req.language).build(req.topic, members)
        r = await self.client.post(f"{self.base_url}/api/chat", json={
            "model": req.ollama_model or self.model,
            "format": "json", "stream": False,
            "messages": [{"role": "system", "content": prompt.system},
                         {"role": "user", "content": prompt.user}],
        }, timeout=600)
        return json.loads(r.json()["message"]["content"])

The cloud generator calls the OpenAI Responses API with a JSON schema response format and the same prompt; both return a raw dict for the normalizer.

10 TTS & voice mapping

Each member is assigned a stable voice (from their profile, or deterministically from their id) so a speaker always sounds the same across a session. Synthesis is provider-agnostic.

src/posedis/services/tts/base.py 
class SpeechSynthesizer(Protocol):
    async def synthesize(self, text: str, voice: str, fmt: str = "mp3") -> bytes: ...

KOKORO_VOICES = ["af_heart", "am_echo", "bf_emma", "af_sky", "am_adam"]

def voice_for(member: Member) -> str:
    return member.voice or KOKORO_VOICES[hash(member.id) % len(KOKORO_VOICES)]

Speaches exposes an OpenAI-compatible endpoint (POST {base}/audio/speech), so the local and cloud synthesizers differ only in base URL, auth, and default model. Generated audio is cached under sessions/{id}/audio/{index}.{fmt} with a voice-mapping JSON for replay.

11 Persistence

SessionStore writes each session as sessions/{id}.json — the serialized Session (events, computed totals, vote, audio metadata). This is the archive-and-replay format (FR-14) and is identical whether the session was generated locally or in the cloud. Listing reads lightweight SessionSummary headers; loading rehydrates via Session.model_validate, so old files are re-validated on read.

🗃️
JSON-on-disk is the v1 store — zero dependencies, human-readable, trivially portable. A future SQLite/SQLModel backend can implement the same SessionStore interface without touching callers.

Secrets bind localhost by default and are read from env/.env or supplied per request. They are never written to session files or logs (FR-15, NFR-1). GET /healthz reports which providers are configured without revealing keys.

13 Frontend

The frontend reuses this very design system (the assets/site.css tokens and the presentation's components) so the running app looks like the pitch. It is plain ES modules served from web/static, with a Jinja2 index.html shell.

  • Setup panel — topic, language, mode (local/remote), provider fields, TTS toggle → POST /api/sessions.
  • Broadcast stage — consumes the SSE stream; renders speaker card, ticker, agenda, scrubber timeline, transport + speed.
  • Vote report — when a vote frame arrives, render the balsavimo protokolas: result badge, procedure/threshold/quorum chips, Už/Prieš/Susilaikė bars, faction table, dissent list.
  • Members modal — GET /api/members; searchable, faction-grouped profiles.
  • Audio + face — play each frame's audioUrl; drive the optional WebGL face's mouth from audio amplitude.
